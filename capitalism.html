โลกธุรกิจเปลี่ยนนิยามของ “สินทรัพย์ที่สร้างกำไร” มาแล้ว 3 ครั้ง — จากสินค้า เป็นแพลตฟอร์ม และกำลังเป็นระบบนิเวศ · หน้านี้อธิบายว่าแต่ละยุคต่างกันอย่างไร PCC อยู่ตรงไหน และต้องเปลี่ยนอะไรบ้าง

อะไรเปลี่ยนบ้าง

อ่านแนวนอนทีละบรรทัด จะเห็นว่ากติกาการแข่งขันเปลี่ยนไปทั้งหมด
หัวข้อ 1 · Industrial 2 · Platform 3 · Ecosystem
เราขายอะไร สินค้าและบริการเป็นชิ้น จบเป็นครั้ง ๆ การเข้าถึงและธุรกรรมบนแพลตฟอร์ม เก็บเป็นรายเดือนหรือต่อครั้ง ผลลัพธ์ที่เกิดจากทั้งเครือข่าย — เราขาย “ระบบที่ทำงานได้” ไม่ใช่ชิ้นส่วน
รายได้มาจากไหน ขายของ ยิ่งขายมากยิ่งได้มาก แต่ต้องผลิตเพิ่มทุกครั้ง ค่าธรรมเนียม ค่าสมาชิก ค่าโฆษณา — โตได้โดยไม่ต้องเพิ่มโรงงาน ส่วนแบ่งจากมูลค่าที่พาร์ทเนอร์สร้าง + รายได้ประจำจากมาตรฐานที่เราวาง
โตอย่างไร เพิ่มกำลังผลิต เพิ่มพนักงาน — โตแบบเส้นตรง เพิ่มผู้ใช้ ต้นทุนต่อรายลดลงเรื่อย ๆ — โตแบบเร่ง เพิ่มพาร์ทเนอร์ ทุกรายที่เข้ามาทำให้ระบบมีค่ากับทุกคนมากขึ้น — Network Effect
ป้องกันคู่แข่งด้วยอะไร ขนาดโรงงานและต้นทุนที่ต่ำกว่า ข้อมูลผู้ใช้และความเคยชิน — ย้ายแล้วเสียประโยชน์ ต้นทุนการย้ายออกของทั้งเครือข่าย — คู่แข่งต้องชวนพาร์ทเนอร์ย้ายตามทั้งระบบ
มองคู่ค้าอย่างไร ซัพพลายเออร์ที่ต้องกดราคาให้ถูกที่สุด ผู้ใช้ที่ต้องดึงเข้ามาให้มากที่สุด หุ้นส่วนที่ต้องทำให้เขาโตไปด้วยกัน — ถ้าพาร์ทเนอร์ไม่กำไร ระบบนิเวศพัง
ความสามารถหลัก วิศวกรรม การผลิต การควบคุมคุณภาพ ซอฟต์แวร์ ข้อมูล ความปลอดภัยไซเบอร์ การออกแบบประสบการณ์ การวางมาตรฐาน การบริหารพาร์ทเนอร์ การกำกับดูแล และความน่าเชื่อถือ
ตัวชี้วัดที่ผู้บริหารดู ยอดขาย · กำลังการผลิต · ต้นทุนต่อหน่วย จำนวนผู้ใช้ · ธุรกรรมต่อเดือน · รายได้ประจำ จำนวนพาร์ทเนอร์ · โซลูชันในมาร์เก็ตเพลส · % รายได้ที่มาจากระบบนิเวศ
3

จุดเปลี่ยน 2 ครั้งที่ต้องข้ามให้ได้

แต่ละครั้งไม่ใช่แค่ทำของเดิมให้ดีขึ้น แต่ต้องเปลี่ยนวิธีคิดเรื่องรายได้
Shift 1

จากขายสินค้า → เป็นเจ้าของแพลตฟอร์ม

Product Platform
  • สิ่งที่ต้องเปลี่ยน: เลิกมองว่าขายของจบแล้วจบเลย — เปลี่ยนอุปกรณ์ที่ขายไปแล้วให้ยัง “คุยกับเรา” ได้ผ่าน IoT และเก็บข้อมูลกลับมา
  • สิ่งที่ต้องสร้าง: ฐานข้อมูลกลางที่เป็นมาตรฐานเดียวกัน · แพลตฟอร์มที่ลูกค้าเข้ามาใช้งานได้เอง · ความปลอดภัยไซเบอร์ที่ลูกค้าองค์กรยอมรับ
  • อุปสรรคที่พบบ่อย: ทำแพลตฟอร์มแต่ไม่มีคนใช้ เพราะไม่ได้แก้ปัญหาที่ลูกค้ามีจริง · และวัฒนธรรมองค์กรยังวัดผลด้วยยอดขายรายชิ้น

✓สิ่งที่ต้องทำ

  • เริ่มจาก API ภายในก่อน เชื่อมระบบในบริษัทให้คุยกันได้ งานวิจัยพบว่าบริษัทที่เริ่มจากจุดนี้เห็นผลเร็วที่สุด
  • เปลี่ยนจากขายอุปกรณ์เป็นขายบริการ เหมือนหลอดไฟ IoT ที่แจกตัวหลอดได้ แล้วเก็บเงินจากบริการบนหลอด
  • เริ่มจากปัญหาต้นทุนข้อมูลที่ลูกค้ามีจริง เช่น บำรุงรักษาเชิงคาดการณ์และจัดการอาคารอัจฉริยะ ซึ่งต้นทุนข้อมูลช่วงใช้งานอาคารสูงถึง 10–20%
  • หาสินทรัพย์ที่ใช้ไม่เต็มกำลัง เครื่องจักรหรืออุปกรณ์ที่ว่างอยู่คือโอกาสแรกของแพลตฟอร์ม
  • สร้างความคล่องตัว 3 ด้านพร้อมกัน วัฒนธรรม (กระจายการตัดสินใจ) · สินทรัพย์ IT (API, SDK, template) · กระบวนการ (นำของเดิมกลับมาใช้ ทดลองแล้วล้มให้เร็ว)

✕สิ่งที่ห้ามทำ

  • ห้ามใช้ IoT เป็นแค่ฟีเจอร์เพื่อขึ้นราคาสินค้า ถ้ารายได้ยังมาจากการขายชิ้นเดียว ก็ยังเป็นโมเดลเดิม
  • ห้ามตัดสินใจด้วยตรรกะของโมเดลเก่า BlackBerry ตัดสินใจถูกทุกครั้งตามโมเดลขายสินค้า แต่โมเดลนั้นเองที่แพ้
  • ห้ามให้หน่วยธุรกิจขายสินค้าเป็นเจ้าของแพลตฟอร์ม แพลตฟอร์มจะถูกวัดด้วยยอดขายเครื่องและถูกตัดงบก่อนเสมอ
  • ห้ามรอให้แพลตฟอร์มสมบูรณ์ก่อนเปิดใช้ เริ่มจากกรณีใช้งานเล็ก ๆ ที่พิสูจน์คุณค่าได้เร็ว แล้วค่อยขยาย
เรียบเรียงจาก Parker & Van Alstyne, “Platform Shift” · ตัวอย่างหลอดไฟ IoT, ต้นทุนข้อมูลในงานก่อสร้าง (IFMA) และงานวิจัย API ของ Benzell, Lagarda & Van Alstyne (2016)
สัญญาณว่าข้ามได้แล้ว
มีรายได้ประจำจากแพลตฟอร์ม และลูกค้าเข้ามาใช้เองโดยไม่ต้องมีพนักงานพาไป
ตัวชี้วัด
% Digital Revenue · จำนวนอุปกรณ์ที่เชื่อมต่อ · ผู้ใช้ที่กลับมาใช้ซ้ำ
Shift 2

จากเจ้าของแพลตฟอร์ม → เป็นผู้จัดวางระบบนิเวศ

Platform Ecosystem
  • สิ่งที่ต้องเปลี่ยน: เลิกทำทุกอย่างเอง — เปิดให้คนอื่นมาสร้างของขายบนแพลตฟอร์มของเรา แล้วเราได้ส่วนแบ่งและได้ข้อมูล
  • สิ่งที่ต้องสร้าง: API และประตูให้นักพัฒนาเข้ามาต่อได้ · มาตรฐานกลางที่ทุกคนยอมรับ · มาร์เก็ตเพลสและกติกาการแบ่งรายได้ที่ยุติธรรม
  • อุปสรรคที่พบบ่อย: กลัวเสียลูกค้าให้พาร์ทเนอร์ จึงไม่กล้าเปิดจริง · และบริหารความสัมพันธ์หลายสิบรายพร้อมกันไม่ไหว

✓สิ่งที่ต้องทำ

  • เลือกแกนหลัก 5–10 อย่างที่เราเก่งจริง แล้วเปิดส่วนที่เหลือให้พาร์ทเนอร์สร้าง
  • ขยาย API ไปสู่คู่ค้า (B2B) และลูกค้า (B2C) ต่อยอดจาก API ภายในที่วางไว้ใน Shift 1
  • ให้พาร์ทเนอร์ทำเงินได้ก่อน ด้วยส่วนแบ่งรายได้ที่ชัด ยุติธรรม และคาดเดาได้
  • คุมคุณภาพการเชื่อมต่อ ด้วยมาตรฐาน กติกา และการคัดกรองพาร์ทเนอร์ เพราะ network effect ต้องมาจากการเชื่อมต่อที่ดี
  • จับต้นทุนข้อมูล ไม่ใช่แค่ขายของเพิ่ม งานออกแบบ วางแผน ประสานงาน และบำรุงรักษา มีมูลค่าสูงกว่าตัววัสดุหลายเท่า
  • ปรับตัวชี้วัดและรางวัล ให้วัดจากความสำเร็จของเครือข่าย และให้รางวัลคนที่ทำให้พาร์ทเนอร์สำเร็จ

✕สิ่งที่ห้ามทำ

  • ห้ามทำทุกฟีเจอร์เอง บทเรียนจาก MySpace ที่แพ้ Facebook เพราะไม่ยอมให้คนนอกมาสร้าง
  • ห้ามแข่งกับพาร์ทเนอร์บนแพลตฟอร์มของเราเอง หรือเปลี่ยนกติกาและส่วนแบ่งกะทันหัน เพราะความเชื่อใจที่เสียไปแล้วเรียกคืนยาก
  • ห้ามเปิดแค่ในนาม API ที่ไม่มีเอกสาร ไม่มีเครื่องมือ ไม่มีที่ให้ทดลอง จะไม่มีใครมาต่อ
  • ห้ามยึดติดกำแพงกันคู่แข่งแบบเดิม ความได้เปรียบย้ายจากการกีดกัน ไปเป็นการดูแลระบบนิเวศให้เติบโต
  • ห้ามวัดผลด้วยยอดขายของเราอย่างเดียว จะทำให้ทีมมองพาร์ทเนอร์เป็นคู่แข่งแย่งรายได้
เรียบเรียงจาก Parker & Van Alstyne, “Platform Shift” (ผู้เขียน Platform Revolution) · ผู้ก่อตั้ง MySpace ยอมรับภายหลังว่าควรโฟกัสเพียงไม่กี่ฟีเจอร์หลัก แล้วปล่อยให้คนอื่นสร้างส่วนที่เหลือ

ถ้าจำได้แค่ 4 ข้อ

สรุปสำหรับปิดการนำเสนอ

จากบริษัทที่ขายสินค้าและระบบ สู่ผู้จัดวางระบบนิเวศโครงสร้างพื้นฐานอัจฉริยะ

1 · นิยามของสินทรัพย์เปลี่ยนไปแล้วเมื่อก่อนสินทรัพย์คือโรงงาน วันนี้คือแพลตฟอร์มและข้อมูล พรุ่งนี้คือเครือข่ายพาร์ทเนอร์ — ถ้ายังวัดคุณค่าด้วยสินทรัพย์แบบเก่า เราจะประเมินตัวเองผิด
2 · ต้องข้ามให้ได้ 2 จุดจากขายของ → เป็นเจ้าของแพลตฟอร์ม แล้วจากแพลตฟอร์ม → เป็นผู้จัดวางระบบนิเวศ · ข้ามไม่ได้ทั้งสองจุด ก็ยังเป็นผู้รับจ้างผลิตเหมือนเดิม
3 · เริ่มจากข้อมูล ไม่ใช่เริ่มจากเทคโนโลยีPhase 1 คือการทำให้ข้อมูลของธุรกิจเดิมเป็นมาตรฐานเดียวกันให้ได้ก่อน — ถ้าฐานนี้ไม่แน่น แพลตฟอร์มที่สร้างทีหลังจะไม่มีอะไรให้ใช้
4 · คูเมืองที่แท้จริงคือเครือข่ายโรงงานลอกได้ แพลตฟอร์มลอกได้ แต่ความไว้ใจของพาร์ทเนอร์หลายสิบรายลอกไม่ได้ — นี่คือเหตุผลที่ปลายทางต้องเป็น Ecosystem ไม่ใช่แค่ Platform
